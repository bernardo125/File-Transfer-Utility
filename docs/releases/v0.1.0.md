First public pre-release of File Throw: send files of any size straight to another computer, with
no server in the middle (no upload, no account, no relay).

## Download

| Platform | File |
|---|---|
| Windows 10/11 (64-bit) | `ftu-windows-amd64.exe` |
| macOS (Apple silicon and Intel) | `ftu-macos-universal.zip` |
| Linux (x86-64, needs `libwebkit2gtk-4.1` and GTK 3) | `ftu-linux-amd64` |

Verify the file against `SHA256SUMS.txt` (`sha256sum`, `shasum -a 256` or `certutil -hashfile <file> SHA256`).

## Read this first

- **This is a pre-release.** It has had code review and automated tests, but **no independent security audit**.
- **The binaries are not code-signed.** Windows SmartScreen and macOS Gatekeeper will warn about an unknown
  publisher (Windows: *More info → Run anyway*; macOS: right-click → *Open*).
- **Linux is the most tested platform.** The Windows and macOS builds come from CI and have had less testing on real machines.
- **Pairing needs you.** After connecting, both screens show a fingerprint. Read it to each other and confirm
  only if it is identical. Nothing can be sent before both of you confirm.
- Some networks cannot be crossed without a relay (symmetric NAT, CGNAT, strict corporate firewalls). There is no relay by design.

## What is in it

- Direct peer-to-peer transfer over QUIC with TLS 1.3, mutual authentication with Ed25519 keys and a hybrid
  X25519 + ML-KEM-768 key exchange (negotiated between two builds of the app).
- Pairing with tokens that carry no secret, and a fingerprint both users confirm.
- The receiver accepts each file explicitly, sees its name and size, and the SHA-256 is checked before the
  file appears. Existing files are never overwritten (`report (1).pdf`).
- Bounded memory: files are streamed in 64 KiB chunks.
- Desktop app (Windows, macOS, Linux) and a terminal mode (`--cli`).

## Security hardening in this release

A security review of the code was done before release. It led to fixes for, among others: unsafe file writes
(overwrite, partial files, symlinks, hostile names), consent bound to one specific offer, validated STUN replies,
a hole-punch that ignores packets from addresses not in the token, key pinning that also holds on resumed
connections, a restricted interface-to-backend surface, a Content-Security-Policy, and dependency updates
(Go 1.26.11, `x/net`, `x/crypto`) that clear all vulnerabilities reported by `govulncheck` for these binaries.

Details, remaining limitations and the status of each finding: [`docs/security`](https://github.com/bernardo125/File-Transfer-Utility/tree/main/docs/security).
To report a vulnerability, see [`SECURITY.md`](https://github.com/bernardo125/File-Transfer-Utility/blob/main/SECURITY.md).

## Known limitations

- Pairing is authenticated by the two users comparing a fingerprint; there is no short-code (PAKE) pairing yet.
- A session key is new each time, so a peer must be confirmed again in every session.
- Received files are not yet marked by the OS as downloaded from the internet.
- No automatic updater: update manually.
